# Twilight and You — 인수인계 문서 (Codex용)

작성일: 2026-10-06
작성 주체: Claude(설계 단계) → Codex(사양서·구현 단계)로 인수인계

## 1. 한 줄 요약

홈화면 위젯에서 **오늘 날씨 + 미세먼지 + 일출/일몰 + 박명(BMNT/EENT/시민박명) 시각**을 한눈에 보는 개인 전용 안드로이드 앱. 원기날씨의 기능은 좋지만 디자인과 구성을 바꿀 수 없어서 직접 만든다.

## 2. 배경과 동기

- 기존에 원기날씨 1x1 / 1x2 위젯으로 오늘 날씨와 미세먼지 주요 지표를 확인해 왔음
- 아쉬운 점: 위젯 디자인·항목 구성을 내 마음대로 할 수 없음, 박명·일출/일몰 시각이 없음
- 사용자는 혼자(스토어 배포 없음). 따라서 범용성보다 **내가 원하는 구성이 정확히 나오는 것**이 우선

## 4. 기능 요구사항

### 4.1 홈화면 위젯 (주 사용 화면)
- 크기: **1x1, 1x2 우선**. 2x1, 2x2는 여유 시
- 기본 표시 항목
  - 현재 기온, 날씨 상태 아이콘
  - 최고/최저 기온
  - 미세먼지(PM10), 초미세먼지(PM2.5) — 등급과 수치
- 추가 표시 항목
  - 일출 / 일몰 시각
  - 박명 시각 (사용자가 선택한 기준 하나)
- 위젯 크기별로 항목 우선순위와 레이아웃을 정할 것 (1x1은 가장 핵심만)
- 위젯 디자인(배경, 글꼴 크기, 항목 배치·표시 여부)은 **앱 설정에서 변경 가능**해야 함
- 위젯 탭 → 수동 새로고침 또는 앱 열기 (설정으로 선택)
- 마지막 갱신 시각 표시

### 4.2 박명(Twilight)
- 기준 3종, 사용자 선택
  - 시민박명: 태양 고도 −6°
  - 항해박명 = **BMNT / EENT**: 태양 고도 −12° (군 기준 용어 그대로 사용)
  - 천문박명: 태양 고도 −18°
- 아침(시작)과 저녁(종료) 각각 표시
- 위젯에는 선택한 기준 하나만, 앱 본 화면에는 3기준 전부 + 일출/일몰을 표로
- 계산 알고리즘은 SPEC에 명시하고, 특정 날짜·위치의 공인 기준값(예: 천문연구원 일출몰 자료)과 비교해 검증

### 4.3 위치와 시간
- 현재 위치(GPS) 자동 / 지역 수동 지정(즐겨찾기 여러 개)
- 현재 시각 기준 자동 갱신. 일몰 이후에는 내일 BMNT를 보여줄지 여부는 설정으로

### 4.4 업데이트
- 갱신 간격 선택: 15분 / 30분 / 1시간 / 3시간 (안드로이드 위젯·WorkManager 최소 간격 제약을 SPEC에 명시)
- 네트워크 실패·오프라인 시 마지막 값 유지 + 갱신 시각으로 "오래됨" 표시

### 4.5 설정 항목 (최소)
- 박명 기준 (시민/항해/천문)
- 갱신 간격
- 위치 모드 (GPS / 수동) 및 즐겨찾기 지역
- 위젯 항목 표시 여부·순서
- 위젯 테마 (배경 투명도, 글꼴 크기)
- 위젯 탭 동작
- 일몰 후 내일 박명 표시 여부

## 5. 미결 사항 (Codex가 질문 목록으로 먼저 정리해 확인받을 것)

1. **minSdk**: 노트9(Android 10까지 업데이트)까지 지원 시 minSdk 29. 노트8까지면 28. Glance 요구사항과 맞춰 추천안 제시
2. Open-Meteo 대기질 모델값과 에어코리아 실측값 차이가 사용자 기준에서 허용 가능한지 — 1단계 완료 후 사용자가 판단
3. 위젯에서 일출/일몰과 박명을 둘 다 보여줄지, 1x1에서는 어느 하나만 보여줄지
4. 날씨 아이콘 세트 (자체 제작 vs 오픈소스 아이콘 팩)
5. 앱 본 화면 범위: 설정 + 오늘 상세만인지, 주간 예보까지 넣을지

## 6. 작업 순서

1. `docs/HANDOVER.md`(이 문서)와 `AGENTS.md`를 읽는다
2. 미결 사항과 모호한 점을 **질문 목록**(5~10개, 각 질문에 추천 답 포함)으로 사용자에게 먼저 제시한다
3. 답을 받은 뒤 `docs/SPEC.md`를 작성한다 (구성은 아래)
4. SPEC 승인 후에만 프로젝트 스캐폴드(Gradle, 패키지 구조, 빈 Glance 위젯)를 만든다
5. 이후 단계별 개발 계획(MVP → 2단계 → 3단계)에 따라 진행

### docs/SPEC.md 구성
1. 개요와 목표 / 비목표
2. 사용자 시나리오 3~4개 (기상 직후, 출근길, 야간 등)
3. 화면·위젯 설계 (크기별 텍스트 와이어프레임)
4. 기능 명세 (4절 항목별 상세)
5. 박명 계산 명세 (수식/알고리즘, 검증 방법과 기준값)
6. 데이터 소스 (Open-Meteo 엔드포인트·파라미터, 호출 한도, 2단계 교체 인터페이스)
7. 설정 항목 전체 목록 (기본값 포함)
8. 기술 스택·아키텍처 (모듈 구조, 데이터 흐름)
9. 단계별 개발 계획과 각 단계 완료 기준
10. 미결 사항과 리스크

## 7. 작업 규칙

- 문서와 사용자 대화는 **한국어**. 코드·식별자·커밋 메시지는 영어
- 코드 작성 전 반드시 SPEC 승인 게이트를 거친다
- API 키·토큰은 절대 커밋하지 않는다 (`local.properties` 또는 환경변수, `.gitignore` 확인)
- 설계 결정은 `docs/DECISIONS.md`에 날짜와 함께 누적 기록
- 브랜치: `main`은 동작하는 상태 유지, 작업은 `feat/*` 브랜치에서
- 원본 자료·참고 문서는 읽기 전용으로 다루고, 산출물은 `docs/`와 소스 트리에만 쓴다
