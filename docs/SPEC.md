작성일: 2026-10-07 (Asia/Seoul)
상태: 2026-10-07 사용자의 “진행합시다”로 구현 착수 승인. v0.1을 구현 기준으로 사용한다. 기본값은 변경 가능한 설정으로 구현한다.

이 문서는 2026-10-07 사용자의 여섯 가지 답변을 우선한다. 이전 기획의 1×1 기능 분리, 세로형 우선, 실측 자료의 후속 도입 제안은 대체한다. 원본 HANDOVER·AGENTS는 인수인계 참고자료다. 사용자 확정 범위와 설계자가 제안하는 기본값은 구분한다.

## 1. 개요와 목표 / 비목표

목표는 개인용 Android 홈화면에서 기온·날씨 이모지·미세먼지와 초미세먼지 각각의 색상·지정 박명 시각을 한눈에 보는 것이다. 앱에서는 실측과 예보를 함께 확인하고 위젯 구성을 편집한다.

제품 범위 제안: 한국 지역, 한국어, 섭씨, 24시간제, APK 직접 설치. Kotlin·Compose·Glance·WorkManager·DataStore와 기기 내 박명 계산은 인수인계 방향을 유지한다. 날씨에도 실황과 예보를 구분해 제공한다. 계정·자체 서버·자동 위치 추적·알림·레이더·장기 통계·주간 날씨는 첫 출시 범위 밖으로 제안한다. 2×2는 후속 후보이며 2×1은 첫 출시 범위로 앞당긴다.

## 2. 사용자 시나리오

1. 아침에 1×1의 기온과 날씨 이모지, 서로 구분된 두 먼지 색상을 확인한다. 같은 카드에서 지정한 박명 시각을 읽는다.
2. 위젯을 눌러 PM10·PM2.5의 관측 농도·측정소·시각과 오늘/내일 예보등급을 비교한다.
3. 저녁에는 선택한 저녁 박명 시각을 확인하고, 다음 사건 모드에서는 해당 시각이 지난 뒤 내일 아침으로 바뀐다.
4. 다른 지역을 보려면 저장된 지역을 선택하거나 현재 위치를 한 번 확인해 저장한다. 이동했다고 위젯의 지역이 자동으로 바뀌지는 않는다.

## 3. 화면·위젯 설계

### 3.1 1×1 필수 구성

요청한 다섯 항목은 기본 구성에서 숨기거나 날씨형/박명형으로 분리하지 않는다. 농도 숫자·최고최저·긴 지역명·예보 상세가 공간 조정 대상이다.

```text
   22°  ☀️
   미 ●  초 ●
   EENT 18:54
```

위 예시는 배치 개념을 설명하는 임의 값이다. 색 점은 왼쪽 PM10, 오른쪽 PM2.5이며 `미`·`초` 라벨을 고정한다. 위젯 안 실제 점은 OS별 모양이 다른 원형 이모지 대신 지정 색상 도형으로 그린다. 날씨에는 사용자가 요청한 이모지를 쓴다.

보조 정보는 아래 원칙으로 반영한다.

- 박명 대상 날짜를 짧게 덧붙인다. `EENT 18:54 · 10/07` 등으로 표기하되 필요한 경우 두 줄로 나눈다.
- 현재값 기준시각은 작은 보조 줄에 남긴다. 여러 관측 항목의 시각이 다르면 가장 오래된 유효 관측시각을 요약 시각으로 쓰고 상세에서 각각 표시한다. 예보 발표시각으로 이를 덮어쓰지 않는다.
- 관측값 일부가 결측이면 그 항목은 `—` 또는 회색 점으로 표시한다. 오래됨·부분 실패 표시를 정상 상태와 구분한다.
- 지역명·측정소명·농도 수치·출처별 시간은 상세 화면에서 바로 확인한다. 1×1의 지역명은 공간이 허용하면 짧게 표시하며 필수 다섯 항목보다 우선하지 않는다.
- 색상만 보이는 등급에는 스크린리더 설명으로 항목·등급·농도·시각을 제공한다. 상세 화면에서는 등급을 텍스트로도 제공한다.

이 구성은 아직 실기기에서 맞춤을 검증하지 않았다. 최종 최소 dp는 S24+와 노트9 런처의 홈 격자에서 결정한다. 기본 글자 크기에서 필수 다섯 항목을 담지 못하면 요구를 조용히 삭제하지 않고 패딩·줄 배치·박명 약칭을 조정한 시안을 제시한다. 큰 글자 모드에서 필요한 위젯 확대 안내도 제공한다.

### 3.2 가로형·세로형

2×1과 1×2는 같은 데이터를 공유하고 방향에 맞게 배치한다. 공통 필수 다섯 항목에 지역·최고최저·농도 숫자·박명 아침/저녁·예보 요약 중 사용자가 선택한 블록을 추가한다. 전부 동시 표시 가능한 것으로 가정하지 않는다.

```text
2×1 가로형 후보
서울  22° ☀️   | 미 ●42  초 ●12
BMNT 05:38     | EENT 18:54
내일 예보: 미 보통 / 초 좋음

1×2 세로형 후보
서울    22° ☀️
최고 24° / 최저 15°
미 ● 42 / 초 ● 12
BMNT 05:38
EENT 18:54
내일 예보 미 보통·초 좋음
```

숫자는 모두 임의 예시다. 실제 렌더링에는 날짜·기준시각을 포함한다. 예보 행은 반드시 `오늘 예보`·`내일 예보`처럼 이름을 붙여 관측 색상과 구별한다. 좁을 때는 최고최저·예보 요약 등 추가 블록 순서대로 줄이고 필수 다섯 항목을 유지한다.

### 3.3 앱 화면

| 화면 | 내용 |
|---|---|
| 현재·예보 | 현재 기온·강수 실황, 날씨 이모지의 근거, 먼지 두 종류의 실측 농도·측정소·시각, 시간별 날씨 예보, 오늘·내일 먼지 예보 |
| 박명 상세 | 오늘·내일, 일출·일몰과 시민/항해/천문박명의 아침·저녁 전체 표 |
| 위젯 편집 | 위젯 선택, 크기별 미리보기, 지역, 박명 선택, 추가 항목·순서, 색상·투명도·글자 크기, 탭 동작 |
| 지역·공통 설정 | 고정 지역 즐겨찾기, 현재 위치 수동 확인, 측정소 선택, 갱신 간격, API 연결 상태, 출처 |

첫 출시 예보 범위는 날씨 향후 24시간 및 오늘·내일 최고최저, 대기질 오늘·내일의 공식 지역별 예보로 제안한다. 아직 발표되지 않은 대상은 `예보 미발표`로 남긴다. 시간별 먼지 농도 예측 그래프는 필수 요구로 추정하지 않는다.

## 4. 기능 상세

### 4.1 실측·예보의 구분

기본 위젯 기온은 기상청 초단기실황, PM10·PM2.5 색은 선택 측정소의 관측값을 기준으로 한다. 앱에서 실측과 예보를 동시에 비교한다. 실측을 구하지 못했을 때 모델 숫자나 예보등급을 실측 자리에 자동 대입하지 않는다.

기상청 초단기실황은 예보구역의 대표 AWS 관측값으로 안내되어 있다. 사용자의 정확한 좌표에서 직접 측정한 값으로 설명하지 않는다. [기상청 단기예보 서비스](https://www.data.go.kr/data/15084084/openapi.do)

에어코리아 서비스는 측정소별 실시간 정보와 대기질 예보통보를 제공한다. 관측은 측정소·관측시각, 예보는 대상 지역·대상 날짜·발표시각을 보존한다. 지역별 예보등급을 측정소의 미래 농도 수치로 변환하지 않는다. [에어코리아 대기오염정보](https://www.data.go.kr/data/15073861/openapi.do)

### 4.2 먼지 색상

각 농도를 독립적으로 분류한다. PM10과 PM2.5를 합쳐 하나의 색으로 만들지 않는다.

| 상태 | 기본 색상 제안 | PM10, μg/m³ | PM2.5, μg/m³ |
|---|---|---:|---:|
| 좋음 | 파랑 | 0–30 | 0–15 |
| 보통 | 초록 | 31–80 | 16–35 |
| 나쁨 | 주황 | 81–150 | 36–75 |
| 매우 나쁨 | 빨강 | 151 이상 | 76 이상 |
| 결측·미수신 | 회색 + 빈 점 또는 대시 | 판정 없음 | 판정 없음 |

농도 구간은 [에어코리아 표시 기준](https://www.airkorea.or.kr/web/main.do)을 참고한다. 위 표 색조는 앱의 제안이며 사용자가 수정할 수 있다. 관측 농도와 API 원문 등급은 따로 보관하고, 평균 기간이 다른 등급을 동일한 것으로 섞지 않는다. 한 시간 관측 농도에 적용한 앱 색상은 상세에서 그 기준을 밝힌다. 공식 일별 예보등급은 제공값 그대로 표시한다.

오래된 값은 기존 등급에 `!` 등 상태 표시를 덧붙인다. 데이터가 없거나 점검 중인 항목에 좋음 색상을 사용하지 않는다. 두 항목의 관측시각이 다르면 상세에 각각 표시한다.

### 4.3 날씨 이모지

유니코드 이모지로 맑음 ☀️, 구름 조금 🌤️, 구름 많음/흐림 ☁️, 비 🌧️, 눈 🌨️, 비·눈 🌨️ 등 짧은 의미 집합을 구성한다. 실제 매핑표는 공급자의 각 코드 체계별로 작성한다. 원자료에 없는 상태를 임의로 생성하지 않는다. 밤의 맑음은 🌙로 표현할 수 있다.

구현 시 초단기실황의 강수형태와 초단기예보의 하늘상태를 구분한다. 실황 강수가 있으면 우선하고, 하늘상태를 예보에서 보충할 때 이모지에 작은 `예` 표지를 붙이며 상세에 대상시각·출처를 남긴다. 비가 관측되지 않았다는 이유만으로 맑음으로 처리하지 않는다. 필요한 입력이 없으면 중립 기호와 `날씨 자료 없음` 설명을 사용한다. [기상청 API허브 변수 안내](https://apihub.kma.go.kr/apiList.do?seqApi=10&seqApiSub=286)

S24+와 노트9에서 이모지 모양·폭은 달라질 수 있으므로 모두 점검한다. 호환성 때문에 이모지를 일반 선 아이콘으로 바꾸는 것은 사용자 요청의 변경이므로 별도로 제안한다.

### 4.4 위치

즐겨찾기 지역을 위젯별로 고정한다. 현재 위치 버튼을 누르면 그때 위치 권한을 요청하고, 확인한 좌표를 사용자가 선택한 지역으로 저장한다. 백그라운드 위치 권한은 요청하지 않는다. 날씨 새로고침 버튼은 저장된 좌표의 데이터만 다시 읽고 GPS를 자동 실행하지 않는다.

권한 거부·GPS 실패 시 기존 고정 지역을 유지한다. 대략적 위치도 허용한다. 위치를 바꾸면 지역 ID·날씨 격자·관측소·예보권역·천문 계산을 함께 갱신한다. 기존 지역의 진행 중 요청은 새 지역 데이터를 덮어쓰지 못하도록 버전을 확인한다.

기상청 위경도→격자 변환은 공식 변환식으로 기기에서 처리한다. 먼지 측정소 목록의 좌표·측정항목을 읽어 가까운 적합 측정소를 추천하고 사용자가 고정할 수 있게 한다. 측정소 좌표 필드는 이름만 보고 경위도를 추측하지 않는다. 공식 예시에서 `dmX`가 위도, `dmY`가 경도로 제시되어 있어 범위와 고정 사례로 검증한다. [측정소정보](https://www.data.go.kr/data/15073877/openapi.do)

초기에는 동일 측정소에서 PM10·PM2.5를 모두 제공하는 곳을 우선한다. 결측을 이유로 측정소를 알림 없이 바꾸지 않는다. 공식 예보권역은 측정소가 아니라 고정 지역에 연결한다. 세부 권역을 자동 판단하지 못하면 지역 설정에서 선택하도록 한다.

### 4.5 갱신·오프라인

공통 희망 간격은 15분·30분·1시간·3시간, 기본 1시간을 제안한다. 실제 작업 실행은 OS 제약으로 늦어질 수 있다. 위젯 날짜 전환도 정확한 시각 실행을 보장하지 않는다. [WorkManager](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

관측·날씨 예보·먼지 예보를 별도 성공/실패 상태로 저장한다. 한 공급자의 실패 때문에 다른 정상 자료를 지우지 않는다. 최근 값과 각 기준시각을 보존한다. 앱 실행과 수동 새로고침은 즉시 갱신을 요청하되 중복은 합친다.

현재 관측값의 유효시각이 2시간을 넘었거나 수신 이후 `max(선택 간격×2, 2시간)`이 지나면 오래됨으로 표시하는 정책을 제안한다. 예보는 해당 대상 기간에 대한 유효한 발표본인지로 판단한다. 과거 날짜의 예보를 오늘 예보로 재사용하지 않는다.

위젯 미실행 중에는 배지가 늦게 바뀔 수 있으므로 시각 자체도 표시한다. 1×1의 날짜·시각 축약 규칙은 실기기 레이아웃 검증 항목이다. 미래 박명의 날짜와 과거 관측자료의 날짜를 같은 의미의 숫자로 혼용하지 않는다.

박명 계산과 저장 자료 재표시는 네트워크 제약이 있는 통신 작업에 종속시키지 않는다. 프로세스 종료·재부팅 후 영구 저장값을 사용하고, 강제 중지 상태에서는 앱 재실행 후 복구한다. 위젯 삭제 시 설정을 정리하고 활성 위젯이 없으면 불필요한 주기 작업을 중지한다.

## 5. 박명 계산

시민 −6°, 항해 −12°, 천문 −18°를 태양 중심의 기하학적 고도로 정의한다. 일출몰은 표준 수평선과 평균 굴절·태양 반지름을 고려한 약 −0.8333°를 쓴다. BMNT/EENT라는 이름은 항해박명에만 쓴다. [USNO 정의](https://aa.usno.navy.mil/faq/RST_defs)

입력은 WGS84 위경도·대상 지역 날짜·IANA 시간대, 출력은 날짜를 포함한 사건별 시각 또는 사건 없음이다. 한국에서는 Asia/Seoul을 사용한다. 개인 좌표가 아닌 공개 시험 좌표를 테스트에 쓴다.

알고리즘 제안: Meeus 기반 태양 적경·적위와 지방시각각을 계산하고, `sin(h) = sin(φ)sin(δ) + cos(φ)cos(δ)cos(H)`로 태양 고도를 얻는다. 지역 날짜의 시작부터 다음 날짜 시작까지 목표 고도 통과 구간을 탐색한 뒤 이분법 등으로 근을 정밀화한다. 상승·하강을 구별하고 내부 해 탐색 정밀도는 1초 이하, 표시 정밀도는 분 단위로 한다. 반올림은 날짜 변환 후 수행하며 다음 사건 선택은 반올림 전 시각으로 한다. 해가 없으면 00:00을 대신 표시하지 않는다.

실제 산·건물·관측 고도·날씨에 따른 가시 일출과 조도 추정은 범위 밖이다. NOAA 설명은 알고리즘 참고로 사용하되 유지보수 중단 안내가 있는 계산기를 유일한 검증 기준으로 삼지 않는다. [NOAA 계산 설명](https://www.gml.noaa.gov/grad/solcalc/calcdetails.html)

### 지정 박명 선택

위젯마다 기준(시민/항해/천문)과 표시 방식(다음 사건/아침 고정/저녁 고정)을 선택한다. 기본은 항해박명·다음 사건을 제안하며 아직 사용자 확정값은 아니다.

- 다음 사건: 오늘 아침 이전→오늘 아침, 아침 이후→오늘 저녁, 저녁 이후→내일 아침.
- 아침 고정: 오늘의 아침 시각을 하루 동안 유지하고 대상 날짜를 함께 표시.
- 저녁 고정: 오늘의 저녁 시각을 하루 동안 유지하고 대상 날짜를 함께 표시.
- 항해박명은 일몰 뒤에도 오늘 EENT를 유지하며 EENT가 지난 뒤 내일 BMNT로 전환.
- 아침·저녁 동시 표시는 확장 위젯에서 제공. 1×1 기본은 지정한 시각 한 개.

검증: 국내 공개 좌표 네 곳 × 계절 대표일, 윤일·연말·날짜 변경·오프라인·사건 없음 사례. 동일 가정의 KASI/USNO 기준자료와 비교해 사건별 표시 오차 2분 이내를 목표로 한다. 아직 계산이나 검증을 수행하지 않았다. 기준값 출처·좌표·시간대·날짜·반올림 방식을 기록하며, 항해·천문박명도 독립된 기준값을 확보해야 완료다.

[기상청](https://www.data.go.kr/data/15084084/openapi.do), [대기질](https://www.data.go.kr/data/15073861/openapi.do), [측정소](https://www.data.go.kr/data/15073877/openapi.do)

인증키·JSON 출력·페이지 처리·발표본 선택을 공급자별로 분리한다. 기상청은 발표 날짜/시각과 격자, 관측은 측정소와 조회 기간, 먼지 예보는 발표 조회일과 오염물질 코드 등을 사용한다. 포털 표시와 실제 요청의 파라미터 대소문자·버전은 최신 첨부 가이드와 인증된 시험 호출로 고정한다. 이 초안에서는 인증 호출을 수행하지 않았다.

먼지 예보는 PM10과 PM25 코드의 자료를 구분하고 대상 날짜·지역에 맞는 가장 최근 발표본을 선택한다. 발표 날짜와 예보 대상 날짜를 같은 것으로 취급하지 않는다. 지역별 문자열 형식의 등급은 정확한 권역 매핑과 오류 처리를 거친다. 수치가 제공되지 않는 예보등급에 임의 농도를 만들지 않는다.

Open-Meteo 날씨·대기질은 비교용 또는 추후 명시적 모델 예보 옵션으로 남긴다. 실측을 충족하는 대체재로 취급하지 않는다. 시간별 먼지 농도 모델을 추가하면 공식 지역별 예보와 별도 열로 표시한다. [Open-Meteo 대기질](https://open-meteo.com/en/docs/air-quality-api)

### 6.2 호출량·키·출처

실제 연결에는 공공데이터포털의 해당 서비스 활용신청과 인증키가 필요하다. 키 없이 박명·샘플 화면·설정 검증은 가능하지만 실측 기능이 완성된 것으로 처리하지 않는다. 실제 키를 채팅이나 저장소에 붙여넣도록 요구하지 않고 구현 때 로컬 입력·보관 경로를 제공한다.

2026-10-07 포털 표시는 기상청 개발계정 10,000, 에어코리아 대기오염정보와 측정소정보 각각 500의 신청 가능 트래픽이다. 정확한 계정별 단위·기간·승인량은 신청 화면과 가이드에서 확인한 뒤 제한기로 적용한다. 여러 위젯이 같은 지역·측정소·발표본을 보면 요청을 공유하고 예보는 매번 같은 발표본을 재다운로드하지 않는다. [기상청 할당 안내](https://www.data.go.kr/data/15084084/openapi.do), [에어코리아 할당 안내](https://www.data.go.kr/data/15073861/openapi.do)

1지역·1측정소에서 관측을 시간마다 받으면 대기질 관측은 약 24회/일, PM10·PM25 예보를 각각 시간마다 조회하는 단순 상한은 추가 48회/일이다. 이는 구현 예산 산정 예시이며 공급자 발표 주기라는 뜻이 아니다. 15분·여러 지역 선택 시에는 계정 할당량을 계산해 설정 제한 또는 캐시 재사용을 적용하고 이를 설명한다.

키는 Git·로그·분석 이벤트·APK 공개 산출물에 노출하지 않는다. 데이터 출처와 라이선스 링크를 상세 화면에 둔다. 원본 관측값·공식 예보문을 보존하고 앱이 덧붙인 색상·상태 설명을 구분한다. 서명키는 저장소 밖에 보관한다. 공개 저장소와 개인용 배포 범위는 별개로 관리한다.

## 8. 기술 스택·아키텍처

단일 `app` 모듈에서 관측 날씨, 날씨 예보, 관측 대기질, 공식 대기질 예보, 천문 계산을 역할별로 분리한다. 각 공급자는 공통 도메인 모델로 변환한다. UI는 공급자 JSON을 직접 해석하지 않는다.

데이터 흐름: 고정 지역·설정 → 공급자별 요청/기기 계산 → 정규화 및 영구 저장 → Compose 상세와 Glance 위젯. 네트워크·천문 작업의 실패 상태는 독립이다.

필드 단위로 값, 단위, 자료 종류, 출처, 측정소/예보권역, 유효시각 또는 대상 기간, 발표시각(있을 때), 수신시각, 상태를 보존한다. DataStore에 공통/위젯별 설정을 저장하고 작은 데이터 캐시는 앱 전용 영구 파일 등으로 원자적 저장한다. 동시 요청의 늦은 응답이 최신 지역·발표본을 덮어쓰지 않도록 한다.

지원 하한은 **Android 10 / minSdk 29를 제안**한다. 노트9의 실제 OS 버전은 미확인이다. S24+에서 우선 검사하고 API 29 에뮬레이터 및 가능하면 노트9 실기기로 검사한다. 미확인 기기에서 동작 검증을 마쳤다고 표기하지 않는다. Android 12 이전 Glance 크기 동작도 확인한다. [Glance 반응형 UI](https://developer.android.com/develop/ui/compose/glance/build-ui)

Kotlin·AGP·Compose·Glance·WorkManager 버전과 targetSdk·compileSdk는 구현 시작 시 안정판 호환 조합을 고정한다. 앱 코드와 스캐폴드는 이 SPEC 전체 승인 후 단계로 둔다.
