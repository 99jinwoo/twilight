## SPEC 승인 기록

2026-10-07: 사용자가 SPEC 초안과 구현 순서를 확인한 뒤 “진행합시다”라고 지시했다. SPEC v0.1을 기준으로 저장소 구성·Android 프로젝트·세 위젯 배치 구현을 시작한다. P001~P008은 변경 가능한 초기 설계값으로 채택한다. 실제 자료 연결과 실기기 검증 완료를 뜻하지 않는다.

## 2026-10-07 · 위젯 기반 구현

- 단계 B에서는 자료 연동 없이 배치를 검증한다. 홈 위젯 기본값은 미연결, 샘플은 사용자 옵트인이다. 앱 미리보기에는 항상 샘플 안내를 붙인다.
- AGP 8.13.2 / Gradle 8.13 / JDK 17 / Kotlin 2.2.21, compile/targetSdk 36으로 고정했다. 호환 기준: [AGP 공식 릴리스 노트](https://developer.android.com/build/releases/agp-8-13-0-release-notes).
- Compose BOM 2025.10.01·Activity Compose 1.11.0은 설정/미리보기, Glance 1.2.0은 홈 위젯, DataStore 1.1.7은 위젯별 영구 설정, WorkManager 2.10.1은 주기적인 재표시에 사용한다. 네트워크 의존성은 아직 추가하지 않는다.
- JUnit 4.13.2와 AndroidX Test 1.6.1/1.6.2·JUnit 확장 1.2.1은 경계값 및 실제 기기의 설정/RemoteViews 검사용이다.
- 이번 미리보기는 불투명도 100%, 저녁 테마를 기본으로 한다. 투명도 25~100%와 세 테마만 구현했고, SPEC의 0%·시스템 테마·먼지색 재정의는 후속 단계다. 좁은 1×1은 필수 항목 유지를 위해 요청한 글자 크기를 줄일 수 있다.
- GitHub Actions와 Android Emulator Runner를 사용해 API 29/35 자동 검사를 구성한다. 샘플 화면 검사가 삼성 실기기 검증을 대체하지는 않는다.
- 최초 문서 작성 시점의 '로컬만 작성' 기록 이후, 승인 문서를 main에 올리고 구현은 feat/widget-foundation 브랜치에서 진행했다. 최신 검증 상태는 STATUS를 따른다.

## 2026-10-07 · v0.2 위젯 피드백 반영

- 사용자 확정: 1×1은 다음 박명을 굵게 위, 직전 박명을 작고 흐리게 아래에 표시한다. '샘플 17시'를 제거하고 어제/오늘/내일을 사건 이름 앞에 붙인다. PM 라벨은 '미'/'초미'. 정보 추가 없이 카드 배경을 88×90dp로 축소한다.
- 사용자 확인: 4×1은 오타다. 1×1·가로 2×1·세로 1×2를 유지한다.
- 사용자 확정: 2×1 오른쪽, 1×2 아래쪽에 아이콘·기온을 포함한 시간별 예보를 추가한다. 기본 4시간, 좁은 가로형은 3 또는 2시간으로 조정한다.
- 선택 로직: 한국 현재 시각 기준으로 직전(≤)/다음(>) 사건을 선택한다. 아침/저녁 고정 설정 UI는 제거하며 기존 저장 필드는 호환을 위해 보존한다. P003~P004의 단일 사건 표시는 대체한다.
- 샘플 정책: 옵트인 유지. 앱 미리보기·설정 및 배포 설명에 가상 자료임을 명시한다. 날짜 선택 로직과 천문 계산 완료를 구분한다. 새로운 의존성은 없다.
- 사용자 보고: v0.1.0-preview가 Note9에서 잘 동작함. 정확한 OS·홈 격자·장시간 동작 및 v0.2 실기기 확인까지 검증한 것으로 확대하지 않는다.

## 2026-10-08 · v0.3 자료·천문 연결

- 사용자 “그럼 다음 단계 진행?”에 따라 병합된 PR #1의 main에서 새 `feat/live-data-and-twilight` 브랜치로 단계 C를 진행한다. 이전 PR을 다시 수정하지 않는다.
- 시민·항해·천문박명은 NOAA/Meeus 식과 기하학적 태양 고도로 오프라인 계산한다. USNO 108개 시각과 비교해 최대 30초 차이를 확인했다. 검증 좌표·일자 밖의 보편적인 정확도를 주장하지 않는다.
- 기상청 최신 첨부(20260928)에 맞춰 실황·단기예보 가용 시각을 발표 +10분으로 잡았다. 실황 강수를 우선하며 단기예보 SKY를 보충하는 아이콘에 ‘예’를 붙이고 앱에 대상·발표시각을 표시한다. 예보를 실측 기온·농도로 대입하지 않는다.
- 에어코리아 실측 ver=1.5의 PM 점검 플래그를 농도보다 우선한다. 측정소 ver=1.1의 dmX=경도/dmY=위도를 사용한다. 이전 사양의 반대 좌표 설명을 바로잡았다.
- API 인증키는 앱의 보안 입력창에서 받아 AndroidKeyStore AES/GCM으로 기기 내부에 암호화한다. 백업하지 않으며 허용된 공공 API HTTPS 요청 외에는 전송하지 않는다. 빌드나 GitHub Secrets에 날씨 키가 필요하지 않다.
- 새 운영 라이브러리는 없다. Android HTTPS/JSON/KeyStore를 사용한다. JVM 단위 검사에서 Android JSON과 같은 파서를 실행하기 위해 `org.json:json:20250517`만 testImplementation으로 추가했다.
- 캐시는 격자·측정소·오염물질별 원자적 파일로 분리한다. 같은 자료는 공유하고 자동 15분/수동 1분 최소 재시도 간격을 둔다. 성공한 같은 발표본은 자동 재다운로드하지 않는다. 부분 실패는 다른 성공 자료를 지우지 않는다.
- 2시간을 넘긴 관측은 위젯에서 비우고 상세에 이전 값·시각·오래됨을 표시한다. 위젯의 표시 밀도를 늘리지 않으면서 오래된 관측을 현재 값으로 보이게 하지 않는 선택이다. OS가 갱신을 미루면 이 처리도 늦어질 수 있다.
- 현재 위치는 버튼을 누를 때 한 번 요청하고 좌표·예보권역을 확인한 뒤 고정한다. 위치 실패·권한 거부·취소는 기존 지역을 보존한다. 백그라운드 위치 권한·추적은 추가하지 않는다.
- 인증키 보유 여부를 질문했지만 답변 전에도 계산·연결 코드와 모의 검사를 진행한다. 실제 인증 성공과 Note9에서 새 버전 실사용은 미검증으로 남긴다.

- 후속 사용자 답변: 인증키가 아직 없으며 신청 안내가 필요함. 세 공식 서비스 활용신청과 앱 직접 입력 절차를 안내했다. 실제 자료 수신 검증은 발급 후 진행한다.
- 코드 `716ad76`은 [CI 37667569031](https://github.com/99jinwoo/twilight/actions/runs/37667569031)에서 API 29/35 각각 7개 검사를 통과했다. 그 실행에서 만든 APK를 재빌드하지 않고 배포한다.

- 열린 PR #2에서 v0.3.1 수정을 이어간다. 측정소 적용 직후 조회를 시작하고, HTTP 오류 본문의 안전한 코드만 보존해 공급자·인증·연결 실패를 구분한다. 운영 앱 의존성은 추가하지 않는다.
- 실제 사용자 키를 대화로 받거나 저장소에 넣지 않는다. 사용자의 실제 예보 실패 원인이 확정되지 않았으므로 앱 개선과 실서비스 복구 확인을 구분한다.

- 측정소 선택 회귀 검사의 스크롤·클릭을 Compose가 제공하는 UI 검사 API로 실행하기 위해 기존 BOM에 맞춘 `androidx.compose.ui:ui-test-junit4`를 androidTestImplementation으로 추가했다. 운영 앱 의존성은 바꾸지 않는다.

## 2026-10-08 · 실제 홈 위젯과 현재 위치 갱신

- 사용자 보고: 새로고침 후 미세먼지 색상이 표시된다. 실측 수신은 사용자 기기에서 확인했고 먼지 예보 정상 수신은 아직 별도로 확인하지 않았다.
- 실제 홈 가로 위젯에서 두 시간만 보이던 폭별 개수 제한을 제거한다. 폭 210dp 미만은 오른쪽에 네 행(시각·아이콘·기온), 이상은 네 열로 표시한다. 자료 자체가 네 시간보다 적으면 제공된 개수만 표시한다.
- 사용자가 선택한 자동 위치 범위는 **앱 실행·새로고침 때**다. 위젯별 옵트인 설정으로 제공하며 기본값은 고정 지역을 유지한다. 앱이 닫히면 마지막 좌표로 기존 주기 갱신을 계속한다. 백그라운드 위치 권한·상시 추적은 추가하지 않는다.
- 현재 좌표·박명·기상청 격자·가까운 PM10/PM2.5 측정소·먼지 예보권역을 함께 갱신한다. 위치 실패 시 기존 지역을 유지하고, 새 좌표에서 측정소나 권역을 확인하지 못하면 이전 지역 값을 섞지 않고 빈 상태와 안내를 표시한다. 자동 모드로 저장된 다른 홈 위젯도 마지막 확인 위치를 공유하며 고정 지역과 스타일은 보존한다.
- Android Geocoder로 지역명을 확인하며 경기·강원 세부 권역은 [에어코리아 공식 FAQ](https://airkorea.or.kr/eng/board/5/1171/?pMENU_NO=144&page=1)의 시군 목록을 사용한다. 알 수 없는 주소는 권역을 추측하지 않는다. 운영 의존성 추가 없음.
